## เฟส 4 — สร้างภาพ (Build) — เอนจินตามโหมดใน TASTE.md

> **Governance — เฟส 4:** เฟสนี้วิ่งตามแพ็กเกจที่ยืนยันในการสัมภาษณ์ล้วนๆ — งานในแผนทั้งหมดคือคลาส A (ทำเอง รายงานผล) ไม่มีจุดตรวจขออนุมัติระหว่างทาง ถ้าพบว่าส่วนใดของแผนทำไม่ได้จริงหรือต้องเบี่ยงด้านรสนิยมในเรื่องที่สัมภาษณ์ไม่ได้ตัดสินไว้ ให้ใช้เส้นทางข้อยกเว้นตาม `references/governance.md` ข้อ 9 (ถามครั้งเดียว บันทึกคำตอบ) — ไม่ใช่แก้เงียบๆ และไม่ใช่หยุดถามเป็นชุด

ก่อนเขียนฉากแรก ให้ทำสี่อย่างนี้ตามลำดับ ข้ามข้อใดข้อหนึ่งแล้วไฟล์วิดีโอที่เรนเดอร์ได้ยังถือว่าเกตตก:

1. อ่าน `references/styles-mg15/<id>.md` ทั้งไฟล์ และคัดลายเซ็นที่เป็นตัวเลข (มุมกล้อง, จำนวนเฟรม, easing, ความหนาเส้น) ลง `direction.json`
2. คัดลอกโฟลเดอร์ `library/extra-styles/demos/<id>/` เข้าโปรเจกต์ แล้วใช้ `grep -n "function \|renderAt\|const "` หาโครงโค้ด อ่านเฉพาะส่วนที่จะเปลี่ยน ห้ามเปิดไฟล์ HTML ทั้งไฟล์ และห้ามเปิดไฟล์ HTML ว่างแล้วเขียนแคนวาสใหม่
3. ใช้ JSON จังหวะของคลิปตัวอย่างที่ sub-agent สรุปไว้ในเฟส 2 แล้วบันทึกว่าเฟรมนี้เลียนแบบจังหวะใด ถ้ายังไม่มี ให้ทำตาม `references/reference-shelf.md` ห้ามเปิดคลิปหรือเฟรมเองใน context หลัก
4. ใช้สคริปต์ใน `scripts/` ตอนตรวจ ห้ามเขียนตัวตรวจเองแล้วให้ผ่านเพราะไฟล์เปิดได้

### เอนจิน: HyperFrames ทำฉาก Remotion ประกอบและส่งออก

ฉบับ `free` ใช้ Remotion อย่างเดียว ทุกช็อตเป็น `[R]` และข้ามตารางด้านล่าง ฉบับ `pro` และ `elite` ใช้ค่าเริ่มต้นคือ Hybrid ใช้สองเอนจินคู่กัน เอเจนต์เลือกเอง ไม่ถามผู้ใช้ ถ้า TASTE.md บันทึกโหมดเอนจินไว้ ให้ทำตามนั้น

| งาน | เอนจิน | แท็กในช็อตลิสต์ |
|---|---|---|
| ฉากโมชันกราฟิก: ตัวอักษรเคลื่อนไหว รูปเปลี่ยนร่าง อนุภาค 3D HUD พลังงานแบบ showreel | HyperFrames + GSAP (Three.js เมื่อแผนสั่ง 3D) | `[H]` |
| ฉากที่ใช้กลไกเดโม elite (หน้า HTML ที่มี `renderAt(t)`) | `harness/render.mjs` ของคลังสไตล์ | `[C]` |
| ฉากเนี๊ยบสะอาด: การ์ด UI ตัวเลขนับ กราฟข้อมูล ภาพถ่ายสินค้า | Remotion | `[R]` |
| ประกอบทุกช็อต + ตัวอักษรไทยชั้นบน + แคปชัน + เสียง + ส่งออกไฟล์สุดท้าย | Remotion (ดูเฟส 6) | — |

ขั้นตอน:

1. เขียนแท็ก `[H]` `[C]` หรือ `[R]` ทุกแถวในช็อตลิสต์ก่อนเริ่มสร้าง
2. สร้างทีละช็อต หนึ่งไฟล์ต่อหนึ่งช็อต ห้ามเขียนทั้งคลิปในไฟล์เดียวครั้งเดียว
3. เรนเดอร์ช็อต `[H]` และ `[C]` เป็นคลิปแยกที่ `shots/<shotId>.mp4` ช็อตที่ต้องซ้อนบนภาพอื่นใช้ไฟล์พื้นโปร่ง (`.webm` หรือ `.mov`)
4. ตรวจแต่ละช็อตด้วยเรนเดอร์ร่างก่อน (`hyperframes render --quality draft` หรือ `render.mjs --scale 0.5 --mb 1`)
5. ช็อต `[R]` อยู่ในโปรเจกต์ Remotion ตัวเดียวกับที่ใช้ประกอบในเฟส 6

ทุกช็อตต้องใช้ beat grid ขนาดเฟรม fps และ design token ชุดเดียวกัน เพราะเฟส 6 จะต่อมันเป็นคลิปเดียว

ถ้าเครื่องไม่มีบาง runtime:

- ไม่มี HyperFrames ให้ทำช็อต `[H]` เป็น `[C]` แล้วบอกผู้ใช้ด้วยภาษาคนธรรมดา
- ไม่มี Remotion ให้ประกอบด้วย ffmpeg ตามเฟส 6 ข้อสำรอง
- งานด่วนหรือมีแค่เบราว์เซอร์กับ ffmpeg ให้ใช้ `[C]` ทั้งคลิป

ฉากหน้าจอแอปหรือเว็บ ให้แคปหน้า HTML จริงเป็นภาพนิ่ง แล้ววาดฉากใหม่ในเอนจิน ใส่ annotation และการขยับได้ ห้ามอัดหน้าจอจริง และห้ามขอให้ผู้ใช้เปิดสิทธิ์ของระบบปฏิบัติการ ตัวเลขและข้อความบนจอต้องมาจากหน้าจริง

### Track A — Remotion (งานสะอาด ลื่น ระดับ launch film)

- โครงโปรเจกต์: `src/index.ts` (registerRoot) → `Root.tsx` (Composition: ขนาด/fps/ความยาวจากแผน) → `src/scenes/*.tsx` → `src/components/*.tsx` แอสเซทผู้ใช้อยู่ใน `public/` เรียกผ่าน `staticFile()`
- สร้างไฟล์ theme กลางก่อนเขียนฉากแรก: สี, ฟอนต์, easing curves, spring presets ทุกคอมโพเนนต์อ่านจากที่นี่เท่านั้น
- ค่าตั้งต้น: `npm install remotion @remotion/cli react react-dom` (+ `@remotion/transitions`, `@remotion/motion-blur`, `@remotion/google-fonts` ตามต้องการ) — แต่ฟอนต์หลักของงานไทยให้ bundle ไฟล์ไว้ในโปรเจกต์เสมอ (ดู thai-layer)
- วิดีโอแอสเซทใช้ `<OffthreadVideo>` เสมอ ไม่ใช้ `<Video>`
- เรนเดอร์: `npx remotion render src/index.ts <CompId> out/video.mp4 --codec h264 --crf 18`
- ถ้า Chromium อัตโนมัติโหลดไม่ได้ (sandbox/ออฟไลน์): หา binary ที่มีอยู่ (`which chromium chromium-browser google-chrome`, โฟลเดอร์ Playwright) แล้วส่ง `--browser-executable=<path>`; ถ้าเจอ error "Old Headless mode has been removed" ให้ใช้ binary แบบ `headless_shell` แทน
- หมายเหตุสัญญาอนุญาต: ตัวไลบรารี Remotion มีเงื่อนไขของมันเอง (ฟรีสำหรับบุคคลและบริษัทขนาดเล็กไม่เกิน 3 คน; ทีมใหญ่กว่านั้นต้องดูเงื่อนไขเชิงพาณิชย์ของ Remotion) — แจ้งผู้ใช้ถ้างานเป็นของบริษัทใหญ่

### Track B — HyperFrames + GSAP (งาน kinetic / ว้าว / 3D)

- ตั้งโปรเจกต์ด้วย `npx hyperframes init` และตรวจสภาพแวดล้อมด้วย `npx hyperframes doctor` (ต้องมี Node และ FFmpeg)
- หลักการเรนเดอร์: HyperFrames seek ไทม์ไลน์ GSAP ที่ pause ไว้ทีละเฟรมใน headless Chrome — เขียนโค้ดแบบ **clock pattern**: มีฟังก์ชัน `draw(t)` ตัวเดียวที่คำนวณสไตล์ทุกอย่างจากเวลา t วินาทีล้วนๆ (เหมือนอ่าน frame ใน Remotion) GSAP มีไว้จัดคิวทวีน ส่วนสถานะสุดท้ายของทุกเฟรมต้องคำนวณซ้ำจาก t ได้เสมอ
- Vendor ทุกไลบรารี (GSAP, Three.js) ลงเครื่อง ห้ามโหลดจาก CDN ตอนเรนเดอร์
- ฟอนต์: วางไฟล์ในโฟลเดอร์แอสเซทและประกาศ `@font-face` ครบทุก family/weight ที่ใช้
- Three.js: ใช้เฉพาะฉากที่แผนระบุว่าต้องการ 3D — สร้าง stage แยกต่อฉาก, กล้องตัดตามบีท (camera cuts), วัสดุเงา/แก้ว/โลหะตามแบรนด์, bloom เฉพาะจุดไฮไลต์จุดเดียว อย่าเปิด 3D ทั้งคลิปถ้าแผนไม่ได้เรียก
- หนึ่งเจ้าของต่อหนึ่ง property: ถ้า GSAP tween แตะ property ไหน ห้าม `draw(t)` แตะ property เดียวกัน

### Track C — HTML seek(t) fallback (ไม่มี runtime เฉพาะทาง)

- ไฟล์ HTML เดียวจบ: มีฟังก์ชัน `render(t)` ที่กำหนดสไตล์ทุกองค์ประกอบจากเวลา t ล้วนๆ **ห้ามใช้ CSS transition, CSS animation, timer หรือ state ที่สะสมข้ามเฟรม** — ทุกเฟรมต้องคำนวณจาก t สดๆ เสมอ (นี่คือเงื่อนไขที่ทำให้เรนเดอร์ซ้ำได้เฟรมเดิมเป๊ะ และเรนเดอร์เฉพาะช่วงที่ขาดได้)
- ตัวจับเฟรม: สคริปต์ (Playwright/Puppeteer) เปิดหน้าเว็บ, เรียก `render(t)` ทีละเฟรมตาม fps, screenshot แต่ละเฟรมเป็น PNG, แล้วรวมด้วย ffmpeg เป็น MP4
- ก่อนจับเฟรมแรก ต้องรอให้ **ฟอนต์และรูปภาพทุกไฟล์โหลดและ decode เสร็จ** (รอทั้ง font loading และ image load events) — เฟรมที่จับก่อนภาพพร้อมจะเพี้ยนและไม่ deterministic (บทเรียนจากงานจริง)
- ค่าสุ่มทุกชนิดต้อง seed คงที่ ห้ามใช้ `Math.random()` เปล่าๆ
- เอนจินนี้คือ fallback ที่พกพาง่ายสุด คุณภาพเพดานต่ำกว่า Track A/B เล็กน้อย แต่ใช้ได้ทุกที่ที่มีเบราว์เซอร์กับ ffmpeg
- ฉากจากเดโม elite ใช้ `library/extra-styles/harness/render.mjs` เป็นตัวจับเฟรม ใส่ `--workers` ตามจำนวนคอร์ลบสอง (Mac 10 คอร์ใช้ 8) เพราะค่าเริ่มต้นคือ 1 และช้ามาก
- ตอนตรวจใช้ `--scale 0.5 --mb 1` ตอนส่งมอบค่อยใช้ค่า motion blur ของเดโม งานจริงครั้งหนึ่งใช้ `workers 1` กับ `mb 3` แล้วคลิป 80 วินาทีใช้เวลาเรนเดอร์ 39 นาที

### ไวยากรณ์การเคลื่อนไหว (Motion Grammar — ใช้ร่วมกันทุกเอนจิน)

- **สเปกทางเข้ามาตรฐาน**: อย่างน้อย 3 คุณสมบัติพร้อมกัน เช่น opacity 0→1 + translateY 24–40px → 0 + scale 0.96→1 (หรือ blur 8px→0 แทน scale) ระยะเวลา 12–24 เฟรม, stagger 3–6 เฟรมระหว่างสมาชิกกลุ่ม
- **easing**: ห้าม linear กับทางเข้า ทางเข้าใช้ spring หรือ ease-out ทางออกใช้ ease-in กล้องใช้ ease-in-out ทางออกสั้นกว่าทางเข้า (ราว 10 เฟรมออก 20 เฟรมเข้า ที่ 30fps)
- **ชั้นภาพ**: ทุกฉากมีอย่างน้อย 3 ชั้นซ้อนกัน (พื้นหลัง ตัวหลัก รายละเอียดหรือข้อความ)
- **ภาพนิ่ง**: ภาพนิ่งทุกภาพต้องมี Ken Burns (ซูมหรือเลื่อนช้าๆ) ห้ามค้างนิ่งสนิท
- **จังหวะฉาก**: HIT (องค์ประกอบหลักลงจอด) → hold นิ่ง 15–20 เฟรม → build ต่อ → HIT ถัดไป
- **สี**: หนึ่งเฟรมมี hero color ได้สีเดียว สีเน้น (accent) ใช้กับองค์ประกอบที่สำคัญที่สุดของเฟรมนั้นเท่านั้น
- **ตัวเลข/เคาน์เตอร์** ต้องหมุนจบและนิ่งสนิทก่อนฉากจบ ห้ามตัดหนีตัวเลขที่ยังวิ่ง
- **Determinism**: เวลา t เดียวกันต้องได้เฟรมเดียวกันเสมอทุกครั้งที่เรนเดอร์ — นี่คือฐานของ QA และการเรนเดอร์ซ่อมเฉพาะช่วง ใครทำลาย determinism (timer, random ไม่ seed, โหลดภาพไม่รอ) ถือว่าบั๊ก
- **กล้อง**: push-in ช้าให้ความรู้สึกพรีเมียม, punch-in cut ให้พลังงาน, orbit ใช้กับสินค้า 3D/ภาพสินค้าฮีโร่ — เลือกตามที่เขียนไว้ในช็อตลิสต์เท่านั้น อย่าเพิ่มการเคลื่อนกล้องที่แผนไม่ได้สั่ง
## โหมดแก้ฟุตเทจเดิม (Editing Existing Footage)

ถ้างานคือแต่งคลิปที่มีอยู่ (ใส่แคปชัน intro/outro เกรดสี) ไม่ใช่สร้างใหม่: `ffprobe` คลิปต้นฉบับก่อนเพื่อรู้ความยาว/fps, ตั้งค่าคอมโพสิชันตามคลิป, วางฟุตเทจเป็นชั้นแอสเซท (Remotion ใช้ `<OffthreadVideo>`), แล้วซ้อนกราฟิก/แคปชัน/grade ตามเฟส 4–6 ตามปกติ แคปชันที่ sync กับคำพูดต้องยึดเวลาจาก transcript จริง ไม่เดา
