## เฟส 0 — สัมภาษณ์แบบ Grill (Taste Interview) — เกิดก่อนทุกอย่าง

หน้าที่ของเฟสนี้: ดึง "DNA รสนิยม" ของผู้ใช้ออกมาให้เป็นรูปธรรม จนทั้งคุณและผู้ใช้เห็นภาพเดียวกันเป๊ะๆ ก่อนเริ่มผลิตใดๆ ผลลัพธ์คือไฟล์ **TASTE.md** (ใช้แม่แบบ `templates/taste-profile.md`) ซึ่งจะกลายเป็นกฎหมายของทุกเฟสถัดไป

**ถ้าโปรเจกต์มี TASTE.md อยู่แล้ว**: โหลดมันขึ้นมา ถามเฉพาะจุดที่เปลี่ยนหรือยังว่าง (delta interview สั้นๆ) แล้วให้ผู้ใช้ยืนยันสิ่งที่เปลี่ยน ไฟล์ที่มีอยู่ไม่ใช่การยืนยัน `packageStatus` ยังเป็น `unconfirmed` จนกว่าผู้ใช้จะยืนยันแพ็กเกจในเฟส `confirm` ห้ามเปิดเฟส `build` จากไฟล์เก่า

### โปรโตคอลการสัมภาษณ์ (ทำตามนี้เป๊ะๆ)

1. **รอบ 1 ถามเป็นคำถามปลายเปิดในแชต** ห้ามมีตัวเลือก ก ข ค เพราะคำตอบต้องเป็นคำของผู้ใช้เอง วิธีถามอยู่ในหัวข้อ «รอบ 1 — ให้เขาเล่าด้วยคำของเขา» รอบ 2 กับรอบ 3 ใช้ป๊อปอัปตัวเลือกของโฮสต์ (Cursor ใช้ AskQuestion, Claude Code ใช้ AskUserQuestion, Antigravity ใช้ ask_question) ถ้าโฮสต์ไม่มีเครื่องมือนั้น ให้พิมพ์เป็นรายการ ข้อแรกคือคำแนะนำ และทุกข้อมีช่องพิมพ์เอง ถ้าคำตอบกลับมาแล้วให้บันทึกทันที
   - **ให้ดูรูปก่อนเลือก:** ก่อนป๊อปอัปเลือกสไตล์และก่อนป๊อปอัปรอบ 3 ให้สร้างบอร์ดรูปด้วย `scripts/board.mjs` (วิธีอยู่ในหัวข้อรอบ 2 และรอบ 3) สคริปต์ทำรูป PNG หนึ่งรูปต่อหนึ่งคำถาม แล้วพิมพ์บรรทัด `IMAGE` ส่งทุกรูปเข้าแชทก่อนป๊อปอัป (Claude desktop ใช้ `SendUserFile` แบบ `display: render` โฮสต์อื่นแนบไฟล์รูป) ชื่อตัวเลือกในป๊อปอัปขึ้นต้นด้วยตัวอักษรการ์ด เช่น «A · ของวางอยู่จริง» ห้ามเปิดหรืออ่านรูปบอร์ดเองในหน้าหลัก ถ้าเครื่องไม่มี Chrome สคริปต์จะเปิดหน้า HTML ให้ผู้ใช้แทน
2. **คำตอบคลุมเครือ = ยังไม่ได้คำตอบ** ถ้าผู้ใช้ตอบว่า "เป็นตัวของตัวเอง" "ดูดี" "น่าเชื่อถือ" ให้ขอตัวอย่างหนึ่งเรื่อง: "ยกตัวอย่างให้ฟังหน่อยได้ไหม"
3. **เฟรมเวิร์กที่ใช้** มีสองอัน และใช้คู่กันเพราะวัดคนละอย่าง
   - Uses and gratifications: ทำคลิปไปเพื่อได้อะไร ยึด Whiting และ Williams (2013) ซึ่งสัมภาษณ์ผู้ใช้โซเชียล 25 คน แล้วได้ 10 เหตุผล และ Lee, Lee, Moon และ Sung (2015) ซึ่งสำรวจผู้ใช้ Instagram 212 คน แล้วได้ 5 แรงจูงใจ คือคุยกับคน เก็บเรื่อง บอกตัวตน หนีจากวัน และแอบดูคนอื่น
   - Imagined audience: โพสต์แล้วมีหน้ารูปใคร และอะไรที่ไม่โพสต์เพราะคนหลายกลุ่มเห็นพร้อมกัน ยึด Marwick และ boyd (2011) ซึ่งสัมภาษณ์ผู้ใช้ Twitter เรื่องผู้ชมในหัวกับการปิดบางเรื่อง
   ห้ามถามว่า "คุณเป็นใคร" ตรงๆ งานสองชิ้นนี้ถามว่าใช้ไปทำอะไร อะไรที่สนุก และนึกถึงคนดูคนไหน
4. **ถามเฉพาะคีย์ที่ `ASK` ของตัวตรวจพิมพ์มา** คีย์ที่มีใน `KEEP` ห้ามถามซ้ำ
   - ถ้าผู้ใช้ให้ไฟล์บรีฟหรือเอกสารมา ให้อ่านก่อนถามข้อแรก แล้ว `answer` คีย์ที่เอกสารตอบไว้ชัดด้วยคำในเอกสาร
   - ถามเฉพาะคีย์ที่เอกสารไม่ได้ตอบ ข้อเท็จจริงในเอกสาร (แพลตฟอร์ม อุปกรณ์บนจอ ความยาว) ห้ามถามซ้ำหรือเสนอตัวเลือกที่ขัดกับมัน
   - ป๊อปอัปหนึ่งครั้งใส่ได้ไม่เกิน 4 คำถาม และแต่ละคำถามมีตัวเลือก 2–4 ข้อ
5. **จบด้วยสรุปโปรไฟล์** เขียน TASTE.md ให้ครบ นำเสนอสรุปให้ผู้ใช้อ่านและยืนยัน (แก้ได้ตอนนี้ ถูกกว่าตอนเรนเดอร์เสร็จมาก) แล้วรัน `summary --stage interview` และจบเทิร์น **ห้ามไปเฟส 1 ก่อนผู้ใช้ตอบสรุปนั้นว่าใช่** แม้ผู้ใช้จะเคยบอกว่า "ทำเลย" ก็ตาม เมื่อเขาตอบว่าใช่ ให้รัน `confirm-interview --user-said "<คำตอบของเขา คัดลอกตรงๆ>"`

### คอร์สอยู่กับที่ คำถามแต่ละรอบไม่ได้อยู่กับที่

ตัวตนห้าคีย์ `who` `why` `lifestyle` `taste` `notMe` อยู่ข้ามงาน งานใหม่ถามเฉพาะคีย์ที่ `ASK` พิมพ์มา `purpose` กับชนิดงานถามทุกงานเพราะเป็นของคลิปนั้น

ลุคคือ `scene` `style` `recipe` `technique` `layout` ครั้งแรกเดินจนครบ งานถัดไปถ้า recall พิมพ์ `keep look` ให้ถามเพียงข้อเดียวว่าใช้ลุคนี้ต่อ เปลี่ยนแต่ของเก่ายังอยู่ หรือไม่เอาลุคนี้แล้ว ใช้ลุคเดิมให้รัน `reuse-look` ไม่เอาแล้วให้รัน `drop-look` แล้วเดินต้นไม้ใหม่ รหัสที่อยู่ในบรรทัด `dropped` ห้ามเอามาเป็นตัวเลือก ถ้ายอมพิมพ์เอง คำสั่ง `answer` จะเอาออกจากรายการนั้น

รอบ 1 เป็นคำถามปลายเปิด รอบ 2 และรอบ 3 เป็นตัวเลือก 2–4 ข้อ ข้อแรกคือคำแนะนำ และมีช่องพิมพ์เอง ลุคใช้คำสั่งด้านล่างเท่านั้น ห้ามแต่งรหัส

ตัวเลือกของลุคมาจากสคริปต์นี้ ห้ามเปิดไฟล์คลังทั้งก้อนระหว่างสัมภาษณ์

```bash
node scripts/choice-menu.mjs scenes
node scripts/choice-menu.mjs styles
node scripts/choice-menu.mjs styles <กลุ่ม>
node scripts/choice-menu.mjs shot-groups
node scripts/choice-menu.mjs shot-group <กลุ่ม>
node scripts/choice-menu.mjs shots <หมวด> [offset]
node scripts/choice-menu.mjs pair <หมวด>
node scripts/choice-menu.mjs techniques <หมวด> [offset]
```

ถ้าผลพิมพ์มี `NEXT <เลข>` ให้ข้อสุดท้ายเป็น «ดูรายการที่เหลือ» แล้วรันคำสั่งเดิมด้วยเลขนั้น ยังไม่บันทึกคำตอบ

### วิธีพูดกับผู้ใช้

คนตอบไม่ใช่นักออกแบบ จิตวิทยาอยู่ในเหตุผลที่คุณเลือกถาม ไม่ได้อยู่ในคำถาม คำถามต้องง่ายเหมือนเพื่อนถามกันในแชต

- คำถามหนึ่งข้อถามเรื่องเดียว สั้นกว่า 15 คำ ใช้คำที่ใช้คุยกันทุกวัน
- ถามเรื่องชีวิต ลูกค้า และของที่เขาเคยเห็น ไม่ถามเรื่องการออกแบบ
- ชื่อตัวเลือกคือของที่นึกภาพออกทันที 2–5 คำ
- คำอธิบายตัวเลือกมีประโยคเดียว บอกว่าคนดูจะเห็นอะไร
- ห้ามซ้อนหลายภาพในบรรทัดเดียว ห้ามใช้คำที่ต้องอ่านซ้ำถึงจะเข้าใจ

บรรทัด `ASK` และ `SAY` ใช้ได้ตามนั้น บรรทัด `RAW` เป็นแค่วัตถุดิบ ต้องเขียนใหม่เป็นภาษาคนก่อนแสดง ก่อนส่งป๊อปอัป ให้ตรวจชื่อและคำอธิบายทุกตัวเลือกด้วย `node scripts/choice-menu.mjs lint "<ข้อความ>"` ถ้าได้ `LINT FAIL` ให้เขียนใหม่ รหัส `ID` ใช้กับ `answer` เท่านั้น ห้ามแสดงให้ผู้ใช้เห็น

| แบบที่ห้าม | แบบที่ใช้ |
|---|---|
| นึกถึงคลิปที่คุณดูจนจบ ภาพแบบไหนที่คุณยังจำได้ (การจัดหน้าจอ) | อยากให้สินค้ากับตัวหนังสืออยู่ตรงไหนบนจอ |
| แผ่นบินมาอัดกระจกแล้วระเบิด: แผ่นภาพหน้าจอบินจากทุกขอบ วนอัดเป็นกระจุกซ้อน แล้วระเบิดออก | รูปหลายใบรวมกันแล้วแตกออก: เผยสินค้าตรงกลางแบบเซอร์ไพรส์ |
| คุณเป็นใคร ตัวตนของแบรนด์คืออะไร | ลูกค้าประจำเล่าถึงร้านคุณให้เพื่อนฟังว่ายังไง |

### รอบ 1 — ให้เขาเล่าด้วยคำของเขา

คำถามตั้งต้นของคีย์ตัวตนอยู่ในตารางด้านล่าง ปรับคำให้เข้ากับงานของเขาได้ แต่ต้องง่ายเท่านี้

1. ส่งคำถามทุกข้อของรอบ 1 ในข้อความเดียว ใส่เลขข้อ 1, 2, 3 และห้ามมีตัวเลือก
2. ใต้แต่ละข้อ ใส่ตัวอย่างคำตอบหนึ่งบรรทัดจากธุรกิจประเภทอื่น เช่น «ร้านขนมปังอาจตอบว่า ลูกค้าบอกว่ากินแล้วนึกถึงบ้านยาย» ตัวอย่างนี้บอกความยาวที่อยากได้ ไม่ใช่คำตอบให้เลือก
3. บอกเขาว่าตอบสั้นๆ ได้ และตอบเป็นเสียงหรือข้อความยาวก็ได้
4. บันทึกด้วยคำของเขาเอง ตัดได้แค่คำซ้ำหรือคำลงท้าย ห้ามเขียนใหม่เป็นภาษาการตลาด
5. ถ้าคำตอบสั้นกว่าหนึ่งประโยค หรือลอยตามข้อ 2 ของโปรโตคอล ให้ถามต่อเพียงครั้งเดียวว่า "ยกตัวอย่างให้ฟังหน่อยได้ไหม"


| คีย์ | ถามว่า | สิ่งที่คุณได้จริง |
|---|---|---|
| `who` | ลูกค้าประจำเล่าถึงคุณให้เพื่อนฟังว่ายังไง | ตัวตนที่คนอื่นเห็น |
| `why` | ทำไมถึงเริ่มทำสิ่งนี้ | เรื่องจริงที่ใช้เล่าในคลิป |
| `lifestyle` | วันหยุดชอบทำอะไร | ภาพ สี และจังหวะที่เขาคุ้น |
| `taste` | มีร้านหรือคลิปไหนที่เห็นแล้วชอบ | ลุคที่เขาชอบจริง |
| `notMe` | คลิปโฆษณาแบบไหนที่เห็นแล้วเลื่อนหนีทันที | สิ่งที่ห้ามทำ |
| `purpose` | ดูคลิปนี้จบแล้ว อยากให้คนทำอะไรต่อ | เป้าหมายของคลิป |

คีย์ตัวตนถามเรื่องชีวิตเขาตามตารางด้านบน เรื่องสีและเสียงถามในรอบ 3 ซึ่งมีคำแนะนำให้เลือก ถ้าเขาไม่อยากตอบข้อไหนในรอบ 1 ให้บันทึกว่า «ไม่ตอบ: <เหตุผลที่เขาให้>» ห้ามเติมคำตอบแทนเขา

ลำดับรอบอยู่ในบรรทัด `ROUNDS` ของตัวตรวจ รอบ 1 คือตัวตนกับ `purpose` รอบ 2 คือลุค รอบ 3 คือ `color` `type` `motion` `sound`

ลำดับลุคครั้งแรก ถ้า `EDITION` เป็น `free` ให้ทำเฉพาะข้อ 1 เพราะฉบับนี้ไม่มีคลังสไตล์

1. `scenes` แล้ว `answer --key scene --value <รหัส>` ถ้าคำตอบ `purpose` จากรอบ 1 ยังลอย ให้ใช้ประโยค `SAY` ของฉากที่เลือกเป็นข้อแนะนำ แล้วถามเขาว่าใช่ไหม
2. `styles` แล้วกลุ่มที่เลือก จนได้รหัสสไตล์ กลุ่ม `glow` มีกลุ่มย่อยอีกชั้น ก่อนถามทุกชั้นให้รัน `node scripts/board.mjs style [กลุ่ม] [offset] --project <โฟลเดอร์งาน> --pick <รหัสที่แนะนำ>` ด้วยกลุ่มและ offset เดียวกับ `choice-menu` บรรทัด `CARDS` บอกว่าตัวอักษรไหนคือรหัสไหน
3. `shot-groups` แล้ว `shot-group` ของกลุ่มนั้น ถ้าในกลุ่มมีหมวดเดียวให้ข้ามไปข้อ 4
4. `shots <หมวด>` จนได้รหัสสูตรหนึ่งตัว
5. `pair <หมวด>` ได้ชื่อหมวดเทคนิค ถ้ารหัสสไตล์เป็น `03-isometric` `04-3d-render` หรือ `22-hud` ให้ใช้หมวด `depth` แทน แล้ว `techniques <หมวด>` จนได้รหัสเทคนิคหนึ่งตัว
6. `techniques layout` จนได้รหัสการจัดหน้าหนึ่งตัว

บันทึกทีละรหัสด้วย `answer --key scene|style|recipe|technique|layout --value <รหัส>` รหัสที่ไม่มีในผลสคริปต์จะถูกปฏิเสธ `set-direction` ใช้รหัส `style` นี้เท่านั้น ในเฟส 2 คำสั่ง `examples` ให้ลิงก์คลิปของสไตล์และสูตรที่เลือก วิธีดูคลิปอยู่ใน `references/reference-shelf.md` ห้ามเปิดคลังวิดีโอ 700 เรื่องให้เลือกใหม่

`taste` เป็นคำพูดเรื่องรสนิยมของคน ไม่ใช่ที่เก็บรหัส งานสร้างเปิดเดโมของรหัสสไตล์ เปิดเฉพาะหัวสูตรนั้น และใช้ `audio.py` กับ `cues.json` ในเดโมเดียวกัน

### รอบ 3 — ปรับให้เป็นของเขา: สี ตัวหนังสือ การขยับ เสียง

ถามรอบนี้หลังลุคล็อกแล้ว เพราะคำแนะนำต้องตั้งต้นจากสไตล์ที่เลือก คีย์คือ `color` `type` `motion` `sound` ถามเฉพาะคีย์ที่ `ASK` พิมพ์มา ส่งทั้งสี่ข้อในป๊อปอัปเดียว

ถามได้ แต่ห้ามถามแบบแบบฟอร์ม เช่น "เอาสีอะไร" "เอาฟอนต์ไหน" "ตัวหนังสือขนาดเท่าไร" คำถามแบบนี้น่าเบื่อ และคนที่ไม่ใช่นักออกแบบตอบไม่ได้

ทำแบบนี้ทุกข้อ:

1. รัน `node scripts/choice-menu.mjs tune <key> <styleId>` คำถามในป๊อปอัปคือบรรทัด `ASK` ทั้งประโยค
2. สร้าง 3 ตัวเลือกตามบรรทัด `BUILD` ข้อแรกคือคำแนะนำของคุณ ตั้งต้นจาก `BASE` แล้วดัดเข้าหาคำพูดและโลโก้ของเขา
3. ชื่อตัวเลือกเป็นภาพหรือสิ่งของ 2–5 คำ เช่น «เขียวใบชากับครีม»
4. คำอธิบายมีประโยคเดียว บอกสิ่งที่คนดูจะเห็นหรือได้ยิน และเหมาะเพราะอะไร โดยใช้คำของเขา ตรวจด้วย `lint` ก่อนส่ง
5. เขียนตัวเลือกทั้งหมดลง `<โฟลเดอร์งาน>/boards/tune.json` แล้วรัน `node scripts/board.mjs tune --project <โฟลเดอร์งาน>` ก่อนส่งป๊อปอัป
   - `headline` `sub` `price` `cta` คือข้อความจริงของเขาจากบรีฟหรือรอบ 1 ห้ามแต่งราคา ถ้าไม่มีราคาให้เว้น
   - `color` แต่ละข้อมี `label` `desc` และสี hex สี่ช่อง `bg` `ink` `accent` `secondary`
   - `type` แต่ละข้อมี `label` `desc` และชื่อฟอนต์ Google Fonts แบบ `ชื่อ-น้ำหนัก` ใน `display` กับ `body` เช่น `Kanit-Bold` ใช้ฟอนต์ที่รองรับภาษาไทยเท่านั้น
   - `motion` แต่ละข้อมี `label` `desc` และ `ease` หนึ่งค่า: `smooth` (ไหลนุ่ม) `bounce` (นุ่มเด้ง) `snap` (เท่ หยุดคม) `float` (ลอยช้า) `spring` (สปริงสั่น)
   - `sound` แต่ละข้อมี `label` `desc` และ `energy` หนึ่งค่า: `soft` (เบา) `steady` (สม่ำเสมอ) `punchy` (กระแทกเป็นจังหวะ) `build` (ไต่ขึ้น)
   - ข้อแรกของทุกหมวดคือคำแนะนำ เรียงตรงกับป๊อปอัป

ตัวอย่างข้อสี สำหรับเจ้าของแบรนด์ที่บอกว่าชอบภาพฟิล์มอุ่นๆ และเกลียดสีนีออน:

| ตัวเลือก | คำอธิบายที่เขาเห็น |
|---|---|
| เขียวใบชากับครีม (แนะนำ) | สีเดียวกับโลโก้ ดูเป็นของธรรมชาติอย่างที่คุณอยากให้คนเชื่อ |
| ไม้อุ่นกับแสงเช้า | อุ่นเหมือนภาพฟิล์มที่คุณชอบ แต่สีโลโก้เด่นน้อยลง |
| ขาวสะอาดแบบญี่ปุ่น | เรียบที่สุด แต่เย็นกว่าและอาจดูเหมือนร้านอื่น |

ถ้าเขาเลือกช่องพิมพ์เอง หรือพูดว่า "แล้วแต่" ให้บันทึกข้อแนะนำ และเขียนลงหมวด 11 ว่าเขามอบให้ตัดสินใจ

บันทึกด้วย `answer --key color|type|motion|sound --value "<ชื่อตัวเลือก>: <คำอธิบายสั้น>"` ค่านี้ติดตัวแบรนด์ข้ามงาน ถ้างานถัดไปเปลี่ยนลุค ให้ถามข้อเดียวว่าจะใช้สี ตัวหนังสือ การขยับ และเสียงชุดเดิมกับลุคใหม่ หรือจะปรับ

ฉบับ `free` ไม่มี `BASE` จากสไตล์ ให้ตั้งต้นข้อแนะนำจากคีย์ `taste` และไฟล์โลโก้จริง

### ถ้าคำตอบยังลอย

ถามครั้งเดียวว่า "ยกตัวอย่างให้ฟังหน่อยได้ไหม" คำตอบนั้นคือสิ่งที่บันทึกลงคีย์ เรื่องจริงหนึ่งเรื่องใช้ทำคลิปได้มากกว่าคำคุณศัพท์หลายคำ

### สิ่งที่ห้ามถามผู้ใช้

ห้ามถามตัวเลขเทคนิค และห้ามให้คนตอบเห็นคำวงการ ตัวเลือกลุคต้องมาจากรหัสในผลสคริปต์เมนูเท่านั้น ถ้ารหัสไม่มีในผลสคริปต์ ห้ามเสนอตัวเลือกนั้น ตัวเลือกรอบ 3 เขียนเองได้ตามกฎของรอบ 3

### กฎการหยุด (Stopping Rules)

สัมภาษณ์จบได้เมื่อ (1) คีย์ใน `ASK` มีคำตอบครบทั้งสามรอบ โดยคีย์รอบ 1 เป็นคำของผู้ใช้ ส่วนรอบ 2 และ 3 ผู้ใช้มอบให้เอเจนต์ตัดสินใจได้ และลุคได้รหัสครบหรือใช้ `reuse-look` (2) เอเจนต์เขียน `TASTE.md` โดยแยกคำพูดของผู้ใช้ออกจากรหัสลุค และทวนให้ผู้ใช้ยืนยัน (3) เอเจนต์เลือกโหมดการสร้างงานเอง ห้ามถามว่าอยากเนี๊ยบหรือหวือหวา ชื่อเอนจินไม่เคยเป็นคำถาม

ไฟล์ `portfolio/dna.md` จำตัวตน ลุคปัจจุบัน สิ่งที่ชอบ สิ่งที่ไม่เอาแล้ว และตอนที่ลุคเปลี่ยน ตัวตรวจเป็นคนเขียนหลัง `confirm-interview` และ `confirm-package` เอเจนต์ห้ามเปิดไฟล์นั้นและห้ามเขียนบันทึกขั้นตอนการทำงานลงไป

### ถ้าผู้ใช้บอกว่า "ทำเลย" หรือ "ไม่อยากตอบเยอะ"

คำนี้แปลว่าให้ถามสั้นลง ไม่ใช่การยืนยัน ทำตามนี้:

1. บอกความเสี่ยงหนึ่งประโยคตรงๆ: "ถ้าถามน้อย คลิปจะออกมาเหมือนคลิปทั่วไปมากขึ้น"
2. ถามรอบ 1 ในข้อความเดียว ไม่เกินสามข้อ ใช้ `who` `notMe` และ `purpose` ก่อน ข้อที่เหลือให้บันทึกว่า «ไม่ตอบ: ผู้ใช้ขอให้ถามน้อย»
3. รอบ 2 และรอบ 3 คุณเลือกข้อแนะนำแทนได้ แล้วแสดงในสรุป
4. แสดงสรุปโปรไฟล์ รัน `summary --stage interview` แล้วจบเทิร์น
5. ด่านยืนยันทั้งสามด่านยังต้องได้คำว่าใช่จากผู้ใช้ ตัวตรวจจะปฏิเสธคำอย่าง "ทำเลยได้ไหม" ที่ไม่มีคำว่าใช่

ถ้าผู้ใช้เริ่มหงุดหงิดกลางทาง ให้เสนอทางลัด: คุณร่างโปรไฟล์จากงานตัวอย่างที่เขาส่งมาให้เขาตรวจแก้แทนการถามต่อ ขั้นสรุปยืนยันโปรไฟล์ห้ามข้าม

> **Governance — เฟส 0:** เฟสนี้คือช่วงที่ 1 (รสนิยม) ของการสัมภาษณ์ครั้งเดียวจบตาม `references/governance.md` ข้อ 2 — ผู้ใช้ยืนยันโปรไฟล์ครั้งแรกด้วย `confirm-interview` แล้วยืนยันทั้งชุดอีกครั้งพร้อมบรีฟและร่างผู้กำกับด้วย `confirm-package` หลังแพ็กเกจยืนยันแล้วเอเจนต์ผลิตแบบ autonomous จนจบและไม่กลับมาถามเรื่องรสนิยมระหว่างทางอีก ทุกคำถามในเฟสนี้เป็นภาษาคนล้วน รอบ 1 เป็นคำถามปลายเปิด รอบ 2 และ 3 เป็นตัวเลือก
