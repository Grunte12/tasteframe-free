# Thai Layer — เลเยอร์ภาษาไทยสำหรับ Motion Graphics

เอกสารนี้เป็นคู่มือเฉพาะทางสำหรับงานโมชันกราฟิกที่ต้องแสดงข้อความภาษาไทย อ่านแล้วนำไปใช้ได้ทันทีโดยไม่ต้องเดา ครอบคลุมเรื่องฟอนต์ การตัดตัวอักษรเพื่อทำแอนิเมชัน ระบบแคปชัน ความเร็วในการอ่าน และเสียงพากย์ภาษาไทย

> หลักคิดรวม: ภาษาไทยไม่ใช่ภาษาอังกฤษที่เปลี่ยนตัวอักษร ระบบเรนเดอร์ การตัดคำ และการจัดจังหวะต้องออกแบบมาสำหรับภาษาไทยตั้งแต่ต้น ถ้ายืมวิธีคิดแบบภาษาอังกฤษมาใช้ตรง ๆ งานจะพังในจุดที่ผู้ชมเห็นชัดที่สุด คือ สระลอย วรรณยุกต์หลุด และแคปชันอ่านไม่ทัน

## 1. ฟอนต์ไทย

### ฟอนต์ที่แนะนำ

> **ลำดับความสำคัญ (อ่านก่อนใช้ไฟล์นี้):** ฟอนต์ในไฟล์นี้คือ **ตัวเลือกที่แนะนำ ไม่ใช่ค่าเริ่มต้นที่ใช้เงียบ ๆ** — ถ้า TASTE.md ยังไม่มีฟอนต์ ให้เสนอ Kanit/Prompt ในรอบถามเรื่องหน้าตา เป็นตัวเลือก "แนะนำ" พร้อมเหตุผล แล้วให้ผู้ใช้เลือก ถ้าอยู่ในโหมดสร้างเลยและผู้ใช้ไม่ได้เลือก ให้ลงบัญชีสมมติฐาน (`governance.md` ข้อ 7) ว่าใช้ Kanit/Prompt — ถ้าโปรไฟล์ของผู้ใช้ระบุฟอนต์แบรนด์ไว้ (TASTE.md ข้อ 3) ให้ใช้ฟอนต์ของโปรไฟล์เสมอและชนะทุกคำแนะนำในไฟล์นี้ตามลำดับความขัดแย้งของ SKILL.md ไฟล์นี้ให้ "วิธีทำงานกับตัวอักษรไทย" ไม่ได้กำหนดหน้าตาของแบรนด์

สำหรับงานโมชันสาย display และงานอธิบายทั่วไป ให้ใช้ 2 ตระกูลนี้เป็นหลัก (เมื่อโปรไฟล์ไม่ได้กำหนดเป็นอย่างอื่น)

| ตระกูล | บทบาทที่เหมาะ | หมายเหตุ |
| --- | --- | --- |
| **Kanit** | พาดหัว, ตัวเลขราคา, CTA, ข้อความหลักบนจอ | ทรงเรขาคณิต อ่านชัดเมื่อตัวใหญ่ น้ำหนักตัดกันชัด เหมาะกับงานขายและงานเปิดตัวสินค้า |
| **Prompt** | พาดหัวรอง, เนื้อความสั้น, คำอธิบายประกอบ | ทรงนุ่มกว่า เป็นมิตรกว่า เหมาะกับงานพรีเมียม งานไลฟ์สไตล์ และงานที่ต้องการโทนอบอุ่น |

ทั้งสองตระกูลรองรับสระและวรรณยุกต์ไทยครบ รูปทรงตัวอักษรสม่ำเสมอเมื่อขยายขนาดใหญ่ และไม่เพี้ยนเมื่อเรนเดอร์ผ่านเบราว์เซอร์หรือเอนจินวิดีโอ

### น้ำหนักที่ใช้

ใช้เฉพาะ 3 น้ำหนักนี้ในงานโมชัน เพื่อให้ลำดับชั้นของข้อความชัดและไฟล์ไม่บวมโดยไม่จำเป็น

- **500 (Medium)** — ข้อความรอง คำอธิบายสั้น บรรทัดสนับสนุน
- **700 (Bold)** — แคปชันบนวิดีโอ ข้อความหลักทั่วไป ตัวเน้น
- **900 (Black)** — พาดหัวฮีโร่ ราคา ตัวเลขสำคัญ คำกระตุ้นเพียงคำเดียวบนจอ

หลีกเลี่ยงการใช้ 300/400 ในงานวิดีโอแนวตั้ง เพราะเมื่อบีบอัดวิดีโอแล้ว เส้นบางจะจางและอ่านยาก โดยเฉพาะบนพื้นหลังที่เป็นภาพถ่าย

### การโหลดฟอนต์ — ต้อง bundle ไฟล์เองเสมอ

อย่าพึ่ง Google Fonts CDN เป็นวิธีเดียวในการโหลดฟอนต์

เหตุผลที่พบจากงานจริง: สภาพแวดล้อมแบบ sandboxed CI หรือเครื่องเรนเดอร์ที่ตัดเน็ตบางส่วน จะดาวน์โหลดฟอนต์จาก CDN ไม่สำเร็จ งานจะ fallback ไปใช้ฟอนต์ระบบโดยไม่เตือน ผลคือพาดหัวหลักเพี้ยนทั้งคลิป กว่าจะรู้ก็ตอนส่งออกไฟล์แล้ว

วิธีที่ถูกต้อง:

1. ดาวน์โหลดไฟล์ฟอนต์ `.woff2` (และ `.ttf` สำรองถ้าเอนจินต้องการ) ของฟอนต์ที่จะใช้จริง — ตามที่ผู้ใช้เลือก (ตัวที่แนะนำคือ Kanit และ Prompt) น้ำหนัก 500 / 700 / 900 หรือฟอนต์ตามที่ TASTE.md กำหนด — เก็บไว้ในโปรเจกต์
2. ประกาศด้วย `@font-face` โดยชี้ไปที่ไฟล์ local ในโปรเจกต์
3. ตั้ง fallback chain ให้ครบทุกครั้ง

```css
@font-face {
  font-family: "Kanit";
  src: url("./fonts/Kanit-Bold.woff2") format("woff2");
  font-weight: 700;
  font-style: normal;
  font-display: block;
}

@font-face {
  font-family: "Kanit";
  src: url("./fonts/Kanit-Black.woff2") format("woff2");
  font-weight: 900;
  font-style: normal;
  font-display: block;
}

.hero-text {
  font-family: "Kanit", "Prompt", "Noto Sans Thai", sans-serif;
}
```

Fallback chain มาตรฐานของสกิลนี้:

```
Kanit → Prompt → "Noto Sans Thai" → sans-serif
```

### กฎเหล็กเรื่องฟอนต์

- **ห้ามพึ่ง system default สำหรับ hero text เด็ดขาด** ฟอนต์ระบบแต่ละเครื่องไม่เหมือนกัน ระยะห่าง สัดส่วนสระ และความสูงของวรรณยุกต์จะเปลี่ยน งานที่จัดไว้พอดีจออาจล้นหรือหดทันที
- ตรวจสอบก่อนเรนเดอร์จริงทุกครั้งว่า ฟอนต์ที่โหลดสำเร็จคือฟอนต์ที่ตั้งใจใช้ (ฟอนต์ที่ผู้ใช้เลือกใน TASTE.md) ไม่ใช่ fallback โดยดูจากตัวอักษรทดลองที่มีวรรณยุกต์ครบ เช่น `ก๋า กี๋ กื๊อ`
- ฝัง/แนบไฟล์ฟอนต์ไปกับโปรเจกต์เสมอ อย่าสมมติว่าเครื่องเรนเดอร์ปลายทางจะมีฟอนต์ติดตั้งอยู่

## 2. กฎ Grapheme Cluster — ห้ามแยกสระและวรรณยุกต์ออกจากพยัญชนะ

> **CRITICAL — จุดนี้ทำให้งานพังมาแล้วในงานทดสอบจริง ไม่ใช่เรื่องทฤษฎี**

### ปัญหาคืออะไร

ตัวอักษรไทย 1 ตัวที่ผู้ชมเห็น อาจประกอบจากหลาย code point ในหน่วยความจำ เช่น พยัญชนะต้น 1 ตัว + สระบน/ล่าง 1 ตัว + วรรณยุกต์ 1 ตัว

สระและเครื่องหมายที่ต้องเกาะกับพยัญชนะต้นเสมอ ได้แก่ สระบน/ล่างและวรรณยุกต์ เช่น

```
่  ๋  ิ  ี  ึ  ื  ุ  ู  ็
```

ถ้าโค้ดตัดข้อความด้วย **index ของ string / code point** (เช่น `str[i]`, `str.split("")`, `[...str]`, หรือ `substring` ทีละตำแหน่ง) จะได้ชิ้นส่วนที่แยกเครื่องหมายเหล่านี้ออกไปลอยเดี่ยว ๆ ผลที่เห็นบนจอคือ

- วรรณยุกต์ลอยแยกจากตัวอักษร หรือลอยผิดตำแหน่ง
- สระบน/ล่างหลุดไปอยู่เหนือช่องว่าง
- รูปคำเพี้ยน อ่านไม่ออกในช่วงที่แอนิเมชันกำลังแยกตัวอักษร

ยิ่งแอนิเมชันแบบ per-letter ที่ตัวอักษรเคลื่อนที่แยกกัน ปัญหานี้ยิ่งชัด เพราะแต่ละชิ้นจะถูกวาดแยกตำแหน่งกันจริง ๆ

### กฎที่ต้องทำ

**ให้ตัดข้อความเป็น grapheme cluster เสมอ** หนึ่ง cluster = หนึ่งหน่วยที่ผู้ชมเห็นเป็นตัวอักษรเดียว รวมพยัญชนะต้น + สระ + วรรณยุกต์ ไว้ด้วยกัน แล้วค่อยนำแต่ละ cluster ไปทำแอนิเมชันเป็นก้อนเดียว

เครื่องมือมาตรฐาน: `Intl.Segmenter` ของ JavaScript ที่มากับเบราว์เซอร์และ Node.js รุ่นใหม่ โดยใช้ `granularity: 'grapheme'`

หากเอนจินที่ใช้ไม่มี `Intl.Segmenter` ให้ใช้ไลบรารี grapheme segmentation ที่เทียบเท่า ห้ามเขียนตัวตัดเองแบบนับ index

### โค้ดตัวอย่าง

```js
// ตัดข้อความเป็น grapheme cluster — วิธีที่ถูกต้องสำหรับภาษาไทย
function splitThaiGraphemes(text) {
  const segmenter = new Intl.Segmenter("th", { granularity: "grapheme" });
  return Array.from(segmenter.segment(text), (part) => part.segment);
}

// ตัวอย่างการใช้งานกับแอนิเมชัน per-letter
const clusters = splitThaiGraphemes("คืออะไร");
// clusters = ["คือ", "อ", "ะ", "ไ", "ร"]
// นำแต่ละ cluster ไปสร้าง <span> แยกกัน แล้ว animate ทั้ง span เป็นหน่วยเดียว
clusters.forEach((cluster, index) => {
  const el = document.createElement("span");
  el.textContent = cluster;
  el.style.display = "inline-block";
  // animate el ทั้งก้อน ห้ามแยกข้างในอีก
});
```

ข้อควรระวังในการใช้งาน:

- ตั้ง `display: inline-block` ที่ระดับ cluster ได้ แต่ **ห้าม** ไปยุ่งกับการวางตำแหน่งของเครื่องหมายภายใน cluster ปล่อยให้ text shaping ของระบบจัดให้
- ถ้าต้องการเอฟเฟกต์แบบเด้งทีละตัว ให้เด้งทั้ง cluster พร้อมกันในเฟรมเดียวกัน
- ทดสอบกับคำที่มีสระบน + วรรณยุกต์ซ้อนกันก่อนส่งออกเสมอ เช่น `กื๊อ`, `จ๋า`, `หนู๋`

### ตัวอย่าง Before / After — คำว่า "คืออะไร"

คำว่า **คืออะไร** เป็นตัวอย่างที่ดี เพราะพยางค์แรกมีทั้งสระบนและรูปที่ซ้อนกันหลายชั้น

**Before — ตัดด้วย code point (ผิด):**

```
"คืออะไร".split("")
// ได้ประมาณ: ["ค", "ื", "อ", "ะ", "ไ", "ร"]  (จำนวนและชิ้นส่วนขึ้นกับวิธีตัด)
// เมื่อ animate แยกกัน: "ื" (สระอือ) จะหลุดจาก "ค" ไปลอยเดี่ยว
// ผลบนจอ: ค + สระลอยแยกกัน อ่านเป็นคำไม่ได้ในช่วงแอนิเมชัน
```

**After — ตัดด้วย grapheme cluster (ถูก):**

```
splitThaiGraphemes("คืออะไร")
// ได้: ["คือ", "อ", "ะ", "ไ", "ร"]
// "คือ" คือ 1 cluster — ค + ื รวมเป็นหน่วยเดียว ไม่แยกจากกันอีก
// เมื่อ animate: ทั้งก้อน "คือ" เคลื่อนที่พร้อมกัน สระยังเกาะพยัญชนะถูกต้องตลอด
```

สรุปให้จำง่าย:

> หน่วยที่เล็กที่สุดสำหรับการทำแอนิเมชันตัวอักษรไทย คือ grapheme cluster ไม่ใช่ตัวอักษรตาม index และไม่ใช่ code point

หลักเดียวกันนี้ใช้กับงาน per-word ด้วย: ตัดคำที่ขอบเขตคำ/วลี แล้วภายในคำนั้นให้คง cluster ไว้ครบ ห้ามเข้าไปแยกข้างในคำอีกชั้นหนึ่ง

## 3. ระบบแคปชัน (Caption System) สำหรับ 9:16 — 1080 × 1920

### โซนปลอดภัย

วิดีโอแนวตั้ง 1080 × 1920 จะถูกทับด้วย UI ของแพลตฟอร์มโซเชียล เช่น ชื่อบัญชี ปุ่มกด คำอธิบาย และแถบโต้ตอบ โดยเฉพาะบริเวณด้านล่างของจอ

กฎการวางตำแหน่ง:

- **เว้นด้านล่าง 15% ของจอไว้** อย่าวางแคปชันหรือข้อมูลสำคัญลงไปในโซนนี้ เพราะจะถูก UI ของแพลตฟอร์มบังหรือทำให้อ่านยาก พื้นที่ประมาณ 288px สุดท้ายจากด้านล่าง (จากความสูง 1920px) ให้ถือเป็นพื้นที่ห้ามวางข้อความสำคัญ
- **เนื้อหาสำคัญให้อยู่ในช่วงกลาง 75% ในแนวตั้ง** คือบริเวณที่สายตาผู้ชมอยู่และไม่ถูกบังทั้งด้านบนและด้านล่าง
- ถ้ามีทั้งพาดหัวและแคปชันในเฟรมเดียวกัน ให้พาดหัวอยู่โซนกลางบน ส่วนแคปชันอยู่เหนือโซนห้ามด้านล่าง ไม่ใช่ชิดขอบล่าง

ภาพจำง่าย ๆ สำหรับเฟรม 1920px:

```
0px        ┌─────────────────┐
           │  โซนบน — ชื่อเรื่องเล็ก / โลโก้รองได้  │
           │                 │
           │  โซนกลาง 75%    │
           │  เนื้อหาสำคัญ    │
           │  พาดหัว + แคปชัน │
           │                 │
1632px     ├─────────────────┤  ← แคปชันต้องจบเหนือเส้นนี้
           │  ห้ามวางสำคัญ   │  ล่าง 15% = UI แพลตฟอร์ม
1920px     └─────────────────┘
```

### ขนาดตัวอักษร

อ้างอิงที่เฟรมกว้าง 1080px:

| ประเภทข้อความ | ขนาดแนะนำ | ฟอนต์ / น้ำหนัก |
| --- | --- | --- |
| พาดหัวหลัก (headline) | **84–120px** | Kanit 900 หรือ 700 |
| บรรทัดแคปชัน (caption line) | **44–56px** | Kanit 700 |
| ข้อความสนับสนุนเล็ก | 36–44px | Kanit / Prompt 500 (ใช้เท่าที่จำเป็น) |

ถ้าข้อความยาว ให้ลดจำนวนคำก่อนลดขนาดตัวอักษร แคปชันที่เล็กกว่า 40px ในจอมือถือจะอ่านแทบไม่ออกหลังการบีบอัดวิดีโอ

### จำนวนบรรทัดและไฮไลต์

- **สูงสุด 2 บรรทัดต่อแคปชัน 1 ชุด** ถ้าเกิน ให้ตัดเป็นแคปชันชุดถัดไปแทนการย่อฟอนต์
- **ไฮไลต์คำสำคัญได้ 1 คำต่อ 1 บรรทัดเท่านั้น** — คำนั้นใช้สี accent ของแบรนด์ + น้ำหนักที่หนักกว่าคำรอบข้าง (เช่น รอบข้าง 700 คำไฮไลต์ 900) ถ้าไฮไลต์หลายคำในบรรทัดเดียว จะไม่มีคำไหนเด่นเลย
- คำที่ควรไฮไลต์: ราคา ตัวเลขผลลัพธ์ คำกริยาหลัก ชื่อคุณสมบัติหลัก — ไม่ใช่คำเชื่อม
- **Word-by-word highlight sync เป็นตัวเลือกเสริม** ใช้เมื่อมีเสียงพากย์และต้องการให้สีไฮไลต์วิ่งตามคำที่กำลังพูดพอดี ช่วยเรื่องความรู้สึกทันสมัย แต่ต้องซิงก์เวลาให้ตรงจริง ถ้าซิงก์ไม่ตรงให้ใช้ไฮไลต์แบบคงที่ต่อบรรทัดแทน จะดูเป็นมืออาชีพกว่า

### การอ่านออกบนพื้นหลังที่เป็นภาพ

เมื่อแคปชันวางทับภาพถ่ายหรือวิดีโอ ให้เพิ่มความอ่านง่ายด้วยวิธีใดวิธีหนึ่งหรือผสมกัน:

- **Stroke** เส้นขอบตัวอักษรสีเข้ม ความหนาพอให้เห็นขอบชัดโดยไม่ทำให้ตัวอักษรบวม
- **Text shadow / drop shadow** เงาอ่อน ๆ ใต้ตัวอักษรเพื่อแยกตัวอักษรออกจากพื้นหลัง
- แถบพื้นหลังโปร่งแสงใต้แคปชันทั้งก้อน (ใช้เมื่อภาพพื้นหลังรกมาก)

ห้ามวางตัวอักษรสีอ่อนลอยบนภาพสว่างโดยไม่มี stroke/shadow เด็ดขาด

### การตัดบรรทัดภาษาไทย

- **ตัดบรรทัดที่ขอบเขตของวลี (phrase boundary)** ให้แต่ละบรรทัดเป็นกลุ่มความหมายที่สมบูรณ์ในตัวเอง
- **ห้ามตัดกลางคำ** และห้ามให้สระ/วรรณยุกต์ของคำนั้นหล่นไปอยู่ต้นบรรทัดถัดไป
- **หลีกเลี่ยงพยางค์เดี่ยวโดด ๆ ค้างอยู่ท้ายบรรทัดหรือต้นบรรทัดเดียว** (orphan) เช่น บรรทัดที่สองเหลือแค่คำสั้น ๆ คำเดียวลอยอยู่ จะดูไม่ตั้งใจและเสียจังหวะการอ่าน ให้ขยับคำก่อนหน้ามาด้วย หรือตัดแคปชันใหม่
- ถ้าประโยคยาวเกิน 2 บรรทัด ให้หั่นตามวลีเป็น 2 แคปชันต่อเนื่อง แทนการบีบข้อความทั้งหมดลงในเฟรมเดียว

ตัวอย่างแนวคิดการตัด:

```
ไม่ดี:  "ครีมตัวนี้ช่วยลดเลือนริ้ว
         รอยภายใน 7 วัน"

ดีกว่า: "ลดเลือนริ้วรอย"
         "เห็นผลใน 7 วัน"
```

## 4. ความเร็วในการอ่านภาษาไทย

ตัวเลขนี้ใช้กำหนดเวลาขั้นต่ำที่แคปชันและการ์ดข้อความต้องค้างอยู่บนจอ ถ้าค้างสั้นกว่านี้ ผู้ชมส่วนใหญ่จะอ่านไม่จบ

- ผู้ชมไทยทั่วไปอ่านข้อความบนจอได้เฉลี่ยประมาณ **4–6 คำต่อวินาที**
- **แคปชัน 1 บรรทัด:** ต้องค้างอย่างน้อย **1.2 วินาที**
- **การ์ดประโยคเต็ม 1 ใบ (sentence card):** ต้องค้างอย่างน้อย **1.7–1.8 วินาที**

วิธีนำไปใช้:

- ก่อนกำหนดจังหวะตัด ให้คำนวณเวลาแสดงจากจำนวนคำก่อน อย่ากำหนดจังหวะจากความรู้สึกอย่างเดียว
- ถ้าบีทหนึ่งมีทั้งภาพเคลื่อนไหวและข้อความ ให้เวลาอ่านเป็นตัวตั้ง แล้วค่อยจัดภาพตาม ไม่ใช่กลับกัน
- ข้อความที่มีตัวเลข ราคา หรือเงื่อนไข ให้บวกเวลาเผื่ออีกเล็กน้อย เพราะผู้ชมต้องหยุดคิด ไม่ใช่แค่อ่านผ่าน
- ตัวเลขนี้เชื่อมตรงไปยังคู่มือจังหวะเวลา (`timing-and-cutting.md`) — บีทที่สั้นกว่าเวลาอ่านขั้นต่ำของข้อความในบีทนั้น ถือว่าออกแบบผิด ต้องขยายบีทหรือลดข้อความ

## 5. เสียงพากย์ไทยด้วย Gemini TTS

ส่วนนี้สรุปวิธีที่ทดสอบแล้วว่าใช้ได้จริง สำหรับการสร้างเสียงพากย์ภาษาไทยด้วยโมเดล TTS ของ Gemini ผ่าน API

### ข้อมูลพื้นฐาน

- **โมเดล:** `gemini-3.8-flash-tts` ผ่าน Gemini API
- **เสียงสำเร็จรูป (prebuilt voices):** มีให้เลือกหลายเสียง ตัวอย่างเสียงที่ใช้งานได้คือ **Kore** ให้ทดลองฟังเสียงตัวอย่างก่อนเลือกเสียงหลักของแบรนด์ แล้วใช้เสียงเดิมต่อเนื่องทั้งซีรีส์เพื่อสร้างการจดจำ
- **รูปแบบไฟล์ที่ได้:** ข้อมูลเสียงดิบแบบ **raw PCM 16-bit, mono, 24kHz** ต้องนำมาห่อ (wrap) เป็นไฟล์ WAV เองก่อนนำไปใช้ในโปรแกรมตัดต่อหรือเอนจินเรนเดอร์ — อย่าสมมติว่าไฟล์ที่ได้จาก API จะเปิดใช้ได้ทันทีในทุกเครื่องมือ

### วิธีควบคุมอารมณ์และจังหวะ — มีวิธีเดียวที่ได้ผล

การควบคุมสไตล์ อารมณ์ และความเร็วของเสียงพากย์ ทำได้ **เฉพาะ** ผ่านโครงสร้างข้อความแบบกำหนดรูปแบบตายตัวเท่านั้น คือต้องมีบล็อก `DIRECTOR'S NOTES` ตามด้วยบล็อก `TRANSCRIPT` ทั้งหมดอยู่ใน text prompt เดียวกัน

โครงสร้างที่ถูกต้อง:

```
### DIRECTOR'S NOTES
Style: [อธิบายอารมณ์และลักษณะเสียง]
Pacing: [อธิบายความเร็ว จังหวะหยุด และน้ำหนักการเน้น]

### TRANSCRIPT
[เฉพาะข้อความที่จะให้พูดเท่านั้น]
```

- บล็อก `DIRECTOR'S NOTES` ใช้บอกสไตล์ เช่น โทนเสียง พลังงาน ความเร็ว และการเว้นจังหวะ โดยมีบรรทัด `Style:` และ `Pacing:` กำกับ
- บล็อก `TRANSCRIPT` ใส่ **เฉพาะคำที่จะออกเสียงจริง** ห้ามใส่คำอธิบาย คำสั่ง หรือเครื่องหมายที่ไม่ได้ต้องการให้พูดปะปนลงไป

### ข้อห้ามสำคัญ — อย่าเขียนประโยคสั่งงานแบบอิสระนำหน้าข้อความ

> **ห้าม** เขียนประโยคคำสั่งอิสระ เช่น "ช่วยพูดประโยคนี้แบบตื่นเต้น ๆ หน่อย" ไว้ก่อนข้อความที่จะให้พูด โดยไม่ได้อยู่ในโครงสร้างบล็อกข้างต้น

เหตุผล: โมเดลจะ **อ่านประโยคคำสั่งนั้นออกเสียงไปด้วย** ราวกับเป็นส่วนหนึ่งของบทพากย์ ผลที่ยืนยันแล้วจากงานทดสอบ: บทที่ควรใช้เวลาพูดประมาณ 2 วินาที กลายเป็นไฟล์เสียงยาว **13.7 วินาที** เพราะโมเดลอ่านทั้งประโยคคำสั่งและบทจริงต่อเนื่องกัน

กฎปฏิบัติ:

- คำสั่งทุกอย่างต้องอยู่ใน `### DIRECTOR'S NOTES` เท่านั้น
- ใน `### TRANSCRIPT` มีแต่คำพูดจริง 100%
- ก่อนเรนเดอร์เสียงเต็มชุด ให้ทดสอบ 1 บรรทัดสั้น ๆ แล้วฟังว่าไม่มีคำสั่งหลุดเข้าไปในเสียง

### ขั้นตอนการทำงานที่แนะนำ

1. แตกบทพากย์เป็น **1 บรรทัดต่อ 1 บีท** (beat) อย่าสร้างไฟล์เดียวเป็นบทพูดยาวทั้งคลิป
2. สร้างเสียงทีละบรรทัดด้วยโครงสร้าง Director's Notes + Transcript
3. **วัดความยาวจริงของไฟล์เสียงแต่ละบรรทัด** (หน่วยวินาที) หลังสร้างเสร็จทุกครั้ง อย่าเดาจากจำนวนคำ
4. นำแต่ละบรรทัดไปวางบน beat grid ตอนมิกซ์เสียง ให้จุดเริ่มของบรรทัดตรงกับจุดเริ่มของบีทที่วางแผนไว้
5. ถ้าบรรทัดไหนยาวเกินบีท ให้แก้ที่บท (ตัดคำ) หรือขยับบีท ไม่ใช่เร่งเสียงจนฟังไม่เป็นธรรมชาติ

### พรีเซ็ต Director's Notes พร้อมใช้ — 3 สไตล์

คัดลอกโครงสร้างไปใช้ แล้วเปลี่ยนเฉพาะข้อความใน Transcript ส่วน Style/Pacing ปรับได้เล็กน้อยตามแบรนด์ แต่อย่าเปลี่ยนรูปแบบบล็อก

#### (a) พรีเซนเตอร์ขายของ — Energetic Sales

เหมาะกับคลิปขายสินค้า โปรโมชัน เปิดตัวสินค้า ต้องการพลังงานและความเร่งเร้า

```
### DIRECTOR'S NOTES
Style: พรีเซนเตอร์ขายของที่สดใส มั่นใจ และชวนตื่นเต้น เสียงยิ้มได้ ฟังแล้วอยากฟังต่อ เน้นคำที่เป็นราคา โปรโมชัน และผลลัพธ์ให้ชัดเป็นพิเศษ น้ำเสียงเป็นกันเองแต่กระฉับกระเฉง ไม่ตะโกน
Pacing: จังหวะเร็วปานกลางถึงเร็ว เว้นจังหวะสั้น ๆ ก่อนคำสำคัญ หยุดเน้นก่อนตัวเลขราคา แล้วเร่งเข้าประโยคปิดการขายโดยไม่ทิ้งช่วงเงียบยาว

### TRANSCRIPT
[ใส่เฉพาะบทพูดตรงนี้]
```

#### (b) พรีเมียม — Calm Premium

เหมาะกับแบรนด์ความงาม สุขภาพระดับพรีเมียม อสังหาริมทรัพย์ และงานที่ต้องการความน่าเชื่อถือแบบนิ่ง

```
### DIRECTOR'S NOTES
Style: เสียงนิ่ง สุขุม และอบอุ่นแบบพรีเมียม โทนต่ำเล็กน้อย พูดชัดทุกพยางค์ ไม่เร่ง ไม่ขายแข็ง ให้ความรู้สึกน่าเชื่อถือและใส่ใจในรายละเอียด เน้นคำสำคัญด้วยการหยุดและลดความเร็ว ไม่ใช่การเพิ่มเสียงดัง
Pacing: จังหวะช้าปานกลาง เว้นช่วงหายใจระหว่างประโยคอย่างเป็นธรรมชาติ ปล่อยให้ประโยคสำคัญค้างจังหวะสั้น ๆ ก่อนไปประโยคถัดไป

### TRANSCRIPT
[ใส่เฉพาะบทพูดตรงนี้]
```

#### (c) เป็นกันเอง — Friendly Explainer

เหมาะกับคลิปอธิบาย วิธีใช้ รีวิว และคอนเทนต์ให้ความรู้ ที่ต้องการให้ผู้ชมรู้สึกเหมือนเพื่อนเล่าให้ฟัง

```
### DIRECTOR'S NOTES
Style: ผู้บรรยายที่เป็นกันเองเหมือนเพื่อนที่รู้เรื่องนี้ดีมาเล่าให้ฟัง เสียงธรรมชาติ มีขึ้นลงตามเนื้อหา ไม่อ่านเป็นท่องจำ ยิ้มในน้ำเสียงเล็กน้อย เน้นคำที่เป็นขั้นตอนหรือข้อควรระวังให้ชัด
Pacing: จังหวะปานกลางเหมือนการพูดคุยจริง เว้นจังหวะตามเครื่องหมายวรรคตอน หยุดสั้น ๆ หลังคำถามเพื่อชวนผู้ชมคิดตาม แล้วจึงเฉลย

### TRANSCRIPT
[ใส่เฉพาะบทพูดตรงนี้]
```

หมายเหตุเรื่องโทนที่เรียกใช้บ่อยในงานไทย: **อบอุ่น** (warm — ใช้พรีเซ็ต b หรือ c ปรับ Style ให้เน้นความนุ่ม), **ตื่นเต้น** (excited — ใช้พรีเซ็ต a), **มั่นใจ** (confident — ใช้พรีเซ็ต b โดยเน้นความชัดและจังหวะที่นิ่ง) ให้เขียนคำเหล่านี้ลงในบรรทัด Style เสมอ แทนการเขียนเป็นประโยคคำสั่งแยกออกมานอกบล็อก

## 6. Fallbacks — ทางเลือกสำรองเมื่อใช้ Gemini TTS ไม่ได้

กฎหลักมาก่อน:

> **ค่าเริ่มต้นของสกิลนี้คือ cloud Gemini TTS เสมอ** ทางสำรองด้านล่างใช้เฉพาะเมื่อผู้ใช้จัดสภาพแวดล้อมที่รองรับให้เท่านั้น อย่าเปลี่ยนค่าเริ่มต้นเองเพียงเพราะทางสำรองเป็นของฟรี

### Edge-TTS

- คือบริการเสียงสังเคราะห์ของ Microsoft ใช้งานฟรี มีเสียงภาษาไทยแบบ neural ให้ใช้
  - เสียงผู้หญิง: `th-TH-PremwadeeNeural`
  - เสียงผู้ชาย: `th-TH-NiwatNeural`
- คุณภาพเสียงดีและเป็นธรรมชาติ เหมาะเป็นทางสำรองเมื่อต้องการเสียงฟรี
- **ข้อจำกัดที่ยืนยันแล้ว:** ต้องใช้เครือข่ายปกติ เพราะการเชื่อมต่อแบบ WebSocket ของบริการนี้ **ถูกบล็อกโดย proxy ของ sandbox บางสภาพแวดล้อม** ทำให้เรียกใช้ไม่สำเร็จในเครื่องเรนเดอร์ที่จำกัดเน็ต อย่าออกแบบ pipeline ที่พึ่ง edge-tts เป็นตัวเดียวในสภาพแวดล้อมแบบ sandbox โดยไม่ได้ทดสอบการเชื่อมต่อก่อน

### โมเดลโอเพนซอร์สแบบ Local

- ตัวอย่าง: **OmniVoice** — โมเดล zero-shot เลียนเสียงได้จากตัวอย่างสั้น ไลเซนส์ Apache 2.0
- **ข้อจำกัด:** ต้องรันบนเครื่องจริงที่มี GPU หรือ Apple Silicon ที่แรงพอ เครื่อง VM ขนาดเล็กแบบ CPU-only ไม่สามารถติดตั้งและรันโมเดลกลุ่มนี้ได้อย่างใช้งานได้จริง ทั้งในแง่เวลาและหน่วยความจำ
- สรุป: ใช้ได้เฉพาะเมื่อผู้ใช้มีเครื่องของตัวเองที่สเปกถึง และเป็นผู้จัดเตรียมสภาพแวดล้อมนั้นเอง

### MMS-TTS ภาษาไทย

- พูดภาษาไทยได้เข้าใจ ฟังรู้เรื่อง เหมาะกับงานต้นแบบหรืองานที่ไม่เน้นอารมณ์เสียง
- **ข้อจำกัด:** น้ำเสียงราบเรียบ (flat) ขาดการเน้นอารมณ์และจังหวะแบบมนุษย์ ไม่เหมาะกับคลิปขายของหรือคลิปที่เสียงพากย์ต้องแบกอารมณ์ของงาน

### ตารางตัดสินใจ

| สถานการณ์ | ตัวเลือกที่ให้ใช้ |
| --- | --- |
| งานปกติทุกกรณี | **Gemini TTS (ค่าเริ่มต้น)** |
| ไม่มี Gemini แต่มีเน็ตปกติและผู้ใช้ยืนยันว่าใช้ได้ | Edge-TTS (`th-TH-PremwadeeNeural` / `th-TH-NiwatNeural`) |
| ผู้ใช้มีเครื่อง GPU / Apple Silicon ของตัวเอง | โมเดล local เช่น OmniVoice |
| ต้องการแค่เสียงต้นแบบชั่วคราว ไม่เน้นอารมณ์ | MMS-TTS Thai |

ถ้าไม่มีสภาพแวดล้อมใดตรงกับทางสำรองเลย ให้แจ้งผู้ใช้ตรง ๆ ว่าติดข้อจำกัดด้านสภาพแวดล้อม แทนการแอบลดคุณภาพเสียงโดยไม่บอก
